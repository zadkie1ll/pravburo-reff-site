# Ручная проверка React-версии сайта

Цель: убедиться глазами, что React-версия ведёт себя как нужно. Первый прогон был до этапа 5
(удаления старых Jinja-страниц) и подтверждён; этот чек-лист остаётся для повторных проверок.

## 1. Запуск и остановка

Демо изолированное: своя временная база в Docker (порт 5433), заглушка CRM (порт 8042, ни одна
заявка не уйдёт в настоящий Bitrix), сайт на порту 8050. Ваша dev-база (5540) и сервер на 8040 не
затрагиваются, настоящие ключи Telegram/SMTP не подхватываются.

Запустить (нужен запущенный Docker):

```bash
scripts/react_demo/start.sh
```

Открыть: <http://127.0.0.1:8050>

Остановить и удалить временную базу:

```bash
scripts/react_demo/stop.sh
```

Если поменяли код фронтенда, пересобрать при запуске:

```bash
scripts/react_demo/start.sh --build
```

Письма с кодами (регистрация, сброс пароля, смена почты) в демо не отправляются, а пишутся в лог:

```bash
grep "Development email" .demo/server.log | tail -3
```

Текущий код 2FA админа `admin@demo.test` (без телефона):

```bash
DATABASE_URL=postgresql+asyncpg://demo:demo@127.0.0.1:5433/demo LEGACY_DATABASE_URL=postgresql+asyncpg://demo:demo@127.0.0.1:5433/legacy PYTHONPATH=. .venv/bin/python scripts/react_demo/demo_data.py code admin@demo.test
```

## 4. Что изменилось осознанно по сравнению со старой версией

Это не баги: скажите, если какое-то из них вам не нравится.

1. «Отметить как выплачено» (админ) теперь спрашивает подтверждение: действие необратимо и рассылает партнёру уведомления.
2. У админа в списке партнёров нет кнопки «Заблокировать» (раньше была, но ничего не делала).
3. Ошибки, которые раньше молча игнорировались, теперь показываются: пустой вопрос FAQ, пустая причина блокировки, несуществующий менеджер, несуществующая заявка.
4. Некорректные значения (месяц 13, вопрос FAQ длиннее 300 символов, `NaN` в ставках) дают понятную ошибку вместо 500.
5. После подтверждения регистрации и сброса пароля админ проходит 2FA (в старом коде для админа она в этих двух местах пропускалась).
6. В профиле код смены почты не хранится в куке открытым текстом.
7. Открытие реферальной формы засчитывается через запрос из браузера, поэтому роботы без JavaScript больше не накручивают «переходы».
8. Ставки сети и кабинет показывают подтверждения/ошибки на странице, а не через перезагрузку.
9. В дереве сети узлы доступны с клавиатуры, партнёр без потомков рисуется (раньше скрипт падал).

## 5. Что здесь проверить нельзя (нужно на вашем окружении)

- Кнопки входа через **Telegram** и **Яндекс**, привязка Яндекса в профиле.
- Настоящие уведомления: email (SMTP), браузерный push, Telegram-бот.
- Реальная капча **Turnstile** с вашими ключами (в демо тестовые).
- Отправка заявки в настоящий CRM/Bitrix.
- Конфиг nginx на сервере: в `/etc/nginx/...` нужно добавить `location /assets/` (в репозитории `deploy/nginx/` уже обновлено).
- Сборка Docker-образа целиком (`docker compose up -d --build`); я проверял только стадию Node.
- Поведение под нагрузкой и на очень большой сети (сотни узлов).
